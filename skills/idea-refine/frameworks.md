# Referencia de Frameworks de Ideacao

Use estes frameworks com critério. Escolha a lente que faz sentido para a ideia em vez de executar tudo mecanicamente. O objetivo e destravar pensamento, não seguir uma checklist.

## SCAMPER

Uma forma estruturada de transformar uma ideia existente aplicando sete operações diferentes:

- **Substitute:** que componente, material ou processo pode ser trocado? E se a tecnologia central mudasse? O público? O modelo de negocio?
- **Combine:** e se isso fosse combinado com outro produto, servico ou ideia? Que duas coisas improvaveis juntas criariam algo novo?
- **Adapt:** com o que isso se parece? Que ideias de outros setores, dominios ou epocas poderiam ser reaproveitadas?
- **Modify (Magnify/Minimize):** e se isso fosse 10x maior? 10x menor? E se uma caracteristica fosse exagerada? E se restasse apenas o minimo absoluto?
- **Put to other uses:** quem mais poderia usar isso? Que outros problemas isso poderia resolver? O que muda em um contexto totalmente diferente?
- **Eliminate:** o que acontece se uma funcionalidade for removida por completo? Como seria a versao sem configuracao? Ou com metade das etapas?
- **Reverse/Rearrange:** e se a ordem dos passos invertesse? E se o usuário fizesse o trabalho em vez do sistema, ou o contrario? E se a cadeia de valor fosse invertida?

**Melhor para:** melhorar ou reimaginar produtos e funcionalidades existentes. Menos util para ideias totalmente greenfield.

## How Might We (HMW)

Reformule problemas como oportunidades usando o formato "Como poderiamos...":

- Comece com uma observacao ou ponto de dor
- Reformule como "Como poderiamos [resultado desejado] para [usuário especifico] sem [restrição principal]?"
- Gere multiplas formulacoes HMW para o mesmo problema; molduras diferentes destravam solucoes diferentes

**Boas qualidades de um HMW:**
- Estreito o bastante para ser acionavel
- Amplo o bastante para permitir criatividade
- Contem uma tensao ou restrição que force criatividade

**Maus sinais em um HMW:**
- Amplo demais: "Como poderiamos deixar os usuários felizes?"
- Estreito demais: "Como poderiamos adicionar um botao na pagina de configuracoes?"
- Solucao embutida: "Como poderiamos criar um chatbot de suporte?"

**Melhor para:** destravar pensamento preso. Quando alguem esta ancorado em uma solucao, puxe de volta para o problema.

## Pensamento por Primeiros Principios

Quebre a ideia em verdades fundamentais e reconstrua a partir delas:

1. **O que sabemos que e verdade?** Não o que foi assumido, mas o que e realmente verdadeiro
2. **O que estamos assumindo?** Liste tudo, inclusive o que parece obvio
3. **Que pressupostos podemos desafiar?** Para cada um, pergunte: isso e uma lei da realidade ou apenas o jeito tradicional de fazer?
4. **Reconstrua a partir das verdades.** Se você so tivesse as verdades fundamentais, o que construiria?

**Melhor para:** escapar do pensamento incremental. Quando toda ideia parece apenas uma pequena melhoria sobre o status quo.

## Jobs to Be Done (JTBD)

Foque no que o usuário esta tentando realizar, e não apenas no que ele diz que quer:

- **Trabalho funcional:** que tarefa ele esta tentando concluir?
- **Trabalho emocional:** como ele quer se sentir?
- **Trabalho social:** como ele quer ser percebido?

Formato: "Quando eu [situacao], quero [motivacao], para poder [resultado esperado]".

**Insight central:** pessoas não compram produtos; elas os contratam para fazer um trabalho. O concorrente real nem sempre esta na mesma categoria.

**Melhor para:** entender o problema real. Quando ainda não esta claro se o problema certo esta sendo resolvido.

## Ideacao Baseada em Restrições

Imponha restrições deliberadamente para forcar solucoes criativas:

- **Restrição de tempo:** "E se você tivesse apenas 1 dia para construir isso?"
- **Restrição de funcionalidade:** "E se isso pudesse ter apenas uma funcionalidade?"
- **Restrição tecnica:** "E se você não pudesse usar [a tecnologia obvia]?"
- **Restrição de custo:** "E se isso precisasse ser gratis para sempre?"
- **Restrição de público:** "E se o usuário nunca tivesse usado um computador antes?"
- **Restrição de escala:** "E se precisasse funcionar para 1 bilhao de usuários? E se fossem apenas 10?"

**Melhor para:** cortar complexidade. Quando a ideia esta crescendo demais ou ficando vaga.

## Pre-mortem

Imagine que a ideia ja falhou. Trabalhe de tras para frente:

1. Estamos 12 meses no futuro. O projeto foi lancado e fracassou. O que deu errado?
2. Liste toda causa plausivel de falha, tecnica, de mercado, de time ou de timing
3. Para cada modo de falha: isso e prevenivel? Isso indica que a ideia precisa mudar?
4. Que falhas sao aceitaveis? Quais matariam o projeto?

**Melhor para:** avaliação da Fase 2. Testar sob pressao ideias que parecem boas, mas ainda não foram tensionadas.

## Inspiracao Analogica

Observe como outros dominios resolveram problemas parecidos:

- Que industria ja resolveu alguma versao desse problema?
- Como isso seria se [empresa/produto especifico] tivesse construido?
- Que sistema natural funciona de forma parecida?
- Que precedente histórico existe?

A chave e encontrar similaridades estruturais, não superficiais. "Uber para X" e superficial. "Um marketplace de dois lados que resolve um problema de confianca entre estranhos" e estrutural.

**Melhor para:** expansao da Fase 1. Gerar variações que sejam genuinamente diferentes da abordagem obvia.
